## 決めたこと

AGENTS.md の6「おまかせの項目」への社長の答え（T-0381 への回答 I-0621〜I-0627。全文のまま）:

- 判断事項1（技術スタック）: A（素の JavaScript（ES モジュール）・ビルドなし・パッケージ0個・検証は node --test）
- 判断事項2（オフラインで使うか）: B（オンライン前提）
- 判断事項3（公開範囲）: A（誰でも開ける URL（講義データは端末内のみ））
- 判断事項4（データ量の目安）: A（20〜100 講義・1講義 10〜30KB（localStorage に JSON 保存））
- 判断事項5（公開先）: A（GitHub Pages（リポジトリを公開にする。無料））
- 判断事項6（バックアップ）: A（作らない（元のスプレッドシートから貼り直す））
- 判断事項7（自動テスト）: B（画面の自動テストも足す（Playwright など。パッケージが増える））

答えどうしの食い違いと、この tasks.md での決め方:

- 判断事項1のパッケージ0個と判断事項7の Playwright: アプリ本体（配信するファイル）はパッケージ0個のまま。Playwright（@playwright/test。配っているのは Microsoft）は画面のテストにだけ使う開発用のパッケージにする。ただし会社の「すでに使っている公式の組織」の基準に当たるか分からないので、入れてよいかは判断待ち（I-0630、kind: package）に出してある。社長の答えが出てから入れる。答えが「入れない」なら、tasks.md の T-010 は行わず、画面は実機で確かめる。
- 判断事項2がオンライン前提: Service Worker でのオフライン保存は作らない。PWA は manifest とホーム画面への追加で満たす（AGENTS.md の5「PWAで作る」）。講義データは端末の localStorage にあるので、開いたあとは通信がなくても表示は動くが、画面のファイル一式の端末保存はしない。
- 判断事項6は作らない: 書き出し・読み込みの機能は作らない。起動時の navigator.storage.persist() を呼ぶだけは行う（機能の追加ではない）。
- 検証コマンドの案: `node --test --test-reporter=dot`（取り込み・判定・保存の関数）と、`npx playwright test`（画面のテスト。Playwright を入れてよい場合だけ）。org.json の verify への登録は社長が行う。

共通の完了条件（どのタスクにも入る）:

- モックは docs/mocks/ の画面ごとの HTML（S-01〜S-04）を読む
- docs/00〜05・AGENTS.md・CLAUDE.md は書き換えない（違いは docs/changes-pending.md に書く）
- スコープ外（docs/00_vision.md の7「やらないこと」）のことはしない

範囲は改訂 v1 の要件（R-001〜R-008。優先度はすべて Must で、Want の要件はない）だけ。
